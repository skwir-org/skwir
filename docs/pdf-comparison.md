# PDFium and Poppler reader comparison

Measured 2026-09-18 on the Linux reference workstation, release builds,
PDFium 7749 (`pdfium-render` 0.8.35) and Poppler 26.06.0 (`poppler-rs` 0.25).
All inputs are generated by `tools/pdf/fixtures.py`; no personal documents,
logs or screenshots are stored here. This supersedes the previous comparison
against Poppler's image-only, per-page CLI renderer.

## Equivalent reader requests

Both workers keep a document open, return outlines on open, render pages
1, 2, 3, 1 with text/link metadata, then search for `needle`. Five runs per
three-page fixture, alternating engine order, 2048-pixel maximum side and
warm OS file cache. New-page time is the median of pages 2 and 3; revisit
rerenders page 1. Neither worker uses the legacy PNG disk cache.

Times include child startup/protocol, native rendering, metadata extraction,
and pixel-file transfer. They exclude the platform manager, GPU upload and
painting, so these are **not end-to-end UI latency measurements**.

Median times in milliseconds:

| Fixture | Engine | Open | First page | New page | Revisit | Search |
|---|---|---:|---:|---:|---:|---:|
| Text | PDFium | 3.94 | 23.53 | 18.72 | 15.68 | 0.21 |
| Text | Poppler | 13.26 | 31.51 | 17.33 | 15.94 | 0.30 |
| Vector | PDFium | 4.06 | 175.09 | 173.14 | 173.71 | 1.81 |
| Vector | Poppler | 12.67 | 129.19 | 115.54 | 116.47 | 3.74 |
| Scan | PDFium | 6.19 | 73.01 | 59.68 | 62.06 | 0.27 |
| Scan | Poppler | 18.57 | 58.84 | 51.77 | 47.04 | 0.28 |

| Fixture | Engine | New-page run range (ms) | CPU (ms) | Peak worker PSS (MiB) | Idle worker PSS (MiB) |
|---|---|---:|---:|---:|---:|
| Text | PDFium | 17.89–19.58 | 50 | 29.18 | 29.18 |
| Text | Poppler | 17.22–19.18 | 60 | 22.75 | 22.75 |
| Vector | PDFium | 166.48–182.82 | 670 | 29.69 | 5.92 |
| Vector | Poppler | 111.68–132.21 | 450 | 22.69 | 22.69 |
| Scan | PDFium | 51.72–63.24 | 180 | 44.04 | 20.27 |
| Scan | Poppler | 48.43–64.03 | 150 | 33.66 | 33.66 |

CPU is child user+system time for open, four renders and search, measured with
`/proc` clock-tick resolution. Peak PSS is sampled every 2 ms plus the final
idle sample; short peaks can be missed. Shared-library mappings, allocator
retention and host load affect these figures. Parent memory and GPU resources
are excluded here. Text/vector searches found three matches; scans had no
text layer and correctly returned zero matches. Every worker exited on close.

PDFium opened faster. New text-page timings were similar; Poppler had lower
peak worker PSS in all three fixtures. Poppler was faster on vector/scan pages
in this paired batch, but this is not a general speed ranking. Two preliminary
batches showed substantial host variation: Poppler's vector new-page median
ranged from 134.52 to 213.39 ms, while PDFium's was 166.78–168.78 ms. Engine
order now alternates and the tool reports the observed range. Keep PDFium
preferred by `auto`; both engines are useful selectable readers.

## Whole application navigation

Fresh isolated configurations, an 1189×1334 Wayland window, synthetic text
PDF in the side panel, 50 alternating page turns:

| Engine | bibli PSS after 10 turns | After 50 turns | Worker after 50 turns | Combined after 50 turns |
|---|---:|---:|---:|---:|
| PDFium | 161.85 MiB | 161.89 MiB | 29.13 MiB | 191.02 MiB |
| Poppler | 161.56 MiB | 161.46 MiB | 23.47 MiB | 184.93 MiB |

Both stabilized across turns. Neither native PDF library was mapped in bibli.
Closing the preview reaped its child for both engines; bibli retained about
161.5 MiB after close because GPU/allocator caches need not return to their
initial footprint. Idle CPU samples over five seconds were 0.6–1.0% of one
core. These are single-session observations, not portable budgets. The
historical 100 MB UI idle target remains an open gate, as recorded in PLAN.

Real Poppler UI checks covered drag selection and clipboard text, search and
highlights on a rotated page, outlines and internal links. HTTP(S) targets
were verified in native metadata; opening a browser was not exercised. The
10k-image grid and 100k-entry list were also scrolled. All 126 default tests
and five installed-renderer tests pass, including selectable/searchable
previews of nine Office formats with both engines. Shared native checks cover
all four rotations with crop, named destinations, empty pages, missing
outlines, dimensions, query limits and corrupt documents. Poppler's native
fixture check also runs in CI.

Filesystem/thumbnail microbenchmarks pass. An initial post-build run missed
`images10k.stream_complete_us` by 135 µs (12,135 vs 12,000); an isolated rerun
of the same binary measured 3,209 µs and passed every budget. No budgets were
changed. This host variation is another reason not to promise renderer speed
from a single sample.

## Reproduce

Enter `nix develop .#pdf`, then:

```sh
cargo build --release -p bibli -p bibli-pdf-worker -p bibli-poppler-worker
python3 tools/pdf/check.py --library "$BIBLI_PDFium_LIBRARY"
python3 tools/pdf/check.py --engine poppler --worker target/release/bibli-poppler-worker
python3 tools/pdf/compare.py --library "$BIBLI_PDFium_LIBRARY" --runs 5
BIBLI_PDF_WORKER="$PWD/target/release/bibli-pdf-worker" BIBLI_POPPLER_WORKER="$PWD/target/release/bibli-poppler-worker" cargo test --release -p bibli-platform real_pdfium_and_poppler_backend_comparison -- --ignored --nocapture
```

The default shell can run `just poppler-check` without PDFium. The broader
installed-tool tests additionally require Poppler CLI utilities, LibreOffice,
bubblewrap and FFmpeg on PATH. Run measurements with other builds/tests and
test UI windows stopped. Keep reports aggregate and synthetic.
