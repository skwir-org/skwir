# Media playback invariants

Read this before touching `crates/media-worker`, `crates/platform/src/media.rs`, `crates/ui/src/media.rs` or the vendored Blade atlas. It is binding, like `AGENTS.md`.

- GStreamer loads only in `bibli-media-worker`. The media provider owns the
  runtime setting; the shared session interface stays independent of GPUI.
- One plugin, `preview-media` ("Preview: audio and video"), registers the
  audio and the video provider and declares every preference of playback:
  the player's own (`preview-media.keep_playing`, `.autoplay`, `.continue`,
  read by the shell's player), loudness and the video engine. Audio and
  video share one player, so a preference of the player is never one
  kind's; with the plugin off there is no player. A changed engine
  re-registers the video provider alone (`PreviewRegistry::unregister`), so
  audio playing goes on. See ADR-016.
- Playback starts paused, unless Play on selection (`preview-media.autoplay`) is
  on, and follows the selected preview and provider lifetime.
  UI controls enqueue only; child cleanup and pixel I/O belong to the manager.
  Show the shared thumbnail immediately, then an optional native-resolution
  representative poster. Play/Seek cancels extraction and rejects late posters;
  poster work must never change the playback position or delay starting playback.
  Fullscreen controls use one cancellable inactivity timer, never an animation
  loop. Stationary pointer events generated by layout must not reset its deadline;
  hover, scrubbing, menus and keyboard focus protect visible controls.
  Pointer movement must not take focus from an open playback popup.
  The controls bar lies over the film and occludes it: the film answers
  clicks, so an overlay on it that does not take the pointer lets a click on
  one of its buttons play or pause as well.
  The picture answers a click like any player (`media::clickable`, on the
  film, the audio figure and the fullscreen canvas): one click toggles
  playback and flashes which way it went (`media::flash`) in the middle of
  the film, or of the cover's disc for music, never of the figure with its
  lines of text, a bounded entrance
  (`FLASH_MS`: held whole for `FLASH_HOLD` of it, then fading, the one
  exception to the 200 ms rule, because a glyph must be read) cleared by one
  timer, never a loop; a double
  click on a film toggles fullscreen after its second click undid the first,
  so playback is as it was.
- Position updates carry command generations too. Discard queued and late old
  state after enqueueing a control. Seek intent stays visible until GStreamer
  completes its asynchronous preroll; an arbitrary timeout or position tolerance
  is not a seek acknowledgment.
- Keep appsink, transfer storage and UI delivery bounded. A frame slot cannot be
  overwritten before acknowledgment. Reject old command generations, release
  replaced GPUI atlas entries, and never write per-frame image files.
- Atlas eviction must cancel pending uploads before recycling texture indices
  and defer physical destruction until in-flight GPU work finishes. GPUI can
  draw several UI scenes before Wayland presents one; keeping only the latest
  preview does not make immediate texture destruction safe. See vendored patch
  `0003-blade-atlas-retirement.patch` and its GPU regression tests.
- GStreamer owns audio/video timing. Decoder events wake the worker and new
  output wakes the UI; never introduce a UI frame timer for playback.
- Track changes re-preroll from READY, then restore position/rate/play state.
  Returning to READY fences the loop's inbox (`Player::fence`): bus messages
  queued before it belong to the abandoned preroll and are dropped, so a
  second change sent before the first has prerolled never selects streams
  from a stream collection decodebin3 no longer knows (which stopped the
  video for good). `tools/media/check.py` switches twice while playing.
  Do not race dynamic subtitle output replacement with paused flushing seeks.
  Keep playbin flags intact and test actual subtitle pixels, not only metadata.
  The manager bounds glibc arenas in the child to limit frame-buffer retention;
  native benchmarks must use the same policy (as `tools/media/check.py` does).
- The decoder is GStreamer's choice, by its feature ranks; bibli does not
  pick one per machine. Where GStreamer ranks a hardware decoder first, the
  worker carries that driver's stack: with NVIDIA's `nvcodec` decoders
  (ranked above `avdec_*`) about 150 MB of CUDA mappings per video worker,
  measured 2026-09-24, on top of the decoder's own frame buffers (about
  60 MB at 1080p, about 400 MB at 4K H.265 with either decoder). An audio
  worker never loads a video decoder and stays near 12 MB PSS. On that
  machine software decoding was lighter and quicker to a first frame at
  1080p and cost 1 to 1.5 more cores at 4K; one machine does not settle the
  choice for others, so the ranks stay as installed. Compare worker memory
  with the same decoder in both runs.
- Generate media with `tools/media/check.py`; report worker-only versus full UI
  latency and combined PSS separately. Clocked fake audio checks timing but do
  not establish audible synchronization or real audio-device behavior.
- A control the worker cannot carry out is a `Rejected` reply carrying the
  command generation, never an `Error`: the manager surfaces it as a transient
  notice and the session continues. Only decoder errors and a lost runtime end
  a session, after which the UI withdraws the controls and returns focus. Gate
  seek and rate on the reported seekability in the UI as well, and skip the
  position restore after a track change on a non-seekable stream.
- The manager owns the single startup deadline and sleeps in one select over
  commands, replies and `CancelToken::subscribe()`; never poll `is_cancelled`
  on a timer from a blocked thread.
- In the worker, bus messages travel through the loop's channel from the sync
  handler, so wake and payload are one object. Install bus and sink handlers
  before the first state change, and never drop or block on that channel from
  a streaming thread.
- GPUI `drop_image` calls run in update/render code, never in prepaint or
  paint: the Blade atlas patch frees retired textures after waiting for the
  previous submission only (see `vendor/gpui/README.bibli.md`).
- The audio picture is `elements/halo.rs`: the cover in a disc, the spectrum
  as rays of dots round it (bass under the cover, treble above, mirrored), a
  glow that swells with the level, in the cover's own colour running to the
  accent. It has no timer: a published spectrum is a frame, and a paused player
  is still (measured: 1 tick of CPU in 4 s). Rays are dots because a circle
  looks the same at any angle, so they are quads in one batch; gpui's path
  pass costs a frame of its own. The cover's colour is worked out once per
  cover (`halo::tint`, weighted by how colourful a pixel is, so a border does
  not wash it out), never per frame. Everything is sized in `paint`.
- Sound. The volume control is perceptual: `Control::Volume` is where the
  control stands and the worker sets `media::amplitude` (its cube) on the
  pipeline, so half the control sounds like half the volume. The audio filter
  is `scaletempo`, which keeps the pitch when the speed changes, followed for
  audio by `spectrum`; either may be missing from an installation and playback
  does without. The spectrum is measured in `SPECTRUM_BINS` linear bins and
  folded by `media::log_bands` into `SPECTRUM_BANDS` logarithmic ones with the
  analysers' usual tilt: music is heard in octaves, and in linear bands nearly
  all of it sits in the first five. What the stream says beyond title, artist
  and album (track, year, genre, codec, bitrate, rate, channels) travels in
  `Playback::details`, bounded by the worker, to the panel's Details.
- Tracks. The files of the same kind (audio, or video) before and after the
  one shown, in the pane's own order, are found when the listing or the entry
  changes (`Shell::media_neighbours`, bounded in reach), never while painting;
  the player shows Previous and Next only when there are any. Stepping moves
  the pane's selection and the preview follows it as always (`ui.media_step`),
  so the list shows what is playing; it keeps playing if it was
  (`PreviewState::autoplay`, the wish Play on selection also makes). What a
  track that plays to its end hands over to is a preference
  (`preview-media.continue`, `player::Continue`): nothing (the default), the next,
  or one at random. The pin draws a shuffle once, starting with the track
  playing, and walks it, so Previous goes back the way Next came; a step to
  another track of the same folder keeps it. Its button is in the player's
  row while there is room and in More after.
- Playlists (`preview-playlists`) are read, not obeyed: tracks are listed,
  nothing is fetched, a remote entry is only named and a missing one marked.
  A track is a member that is a file of its own (`Member::own_file`): nothing
  is written and nothing removed. Opening one from the list remembers the rows
  as shown (`preview::Queue`), and the player's Previous, Next and hand-over
  then walk that queue instead of the folder; leaving the playlist forgets it.
- Keep playing (`player.rs`). A preview dies with the selection and its media
  session with it; pinned, the session belongs to the window. A track is
  pinned when it starts to play (`Shell::media_started`, from the one path
  every start takes, `media_send`) while Keep playing
  (`preview-media.keep_playing`, a row of More) is on, the default; `ui.media_pin`
  pins or lets go of one track by hand. A media session has a lifetime of its own
  (`MediaState`), not the reader's, which the pin takes with it and gives
  back when unpinned, so neither going away ends the other's session. The
  panel shows the pinned session again whenever its file is selected, taking
  its state and its frames live (`MediaState::show_live`, no poster to wait
  behind, the pin's cover or last frame shown until the next): the preview
  worker does not open a player for the pinned file at all, so there is
  never a second player for one file. A pin set, moved or let go starts a
  new generation, so a track still opening for the old one is dropped. Starting another track while
  one is pinned moves the pin, or with Keep playing off stops it: never two
  playing at once. While the panel shows the pinned session, steps (the
  panel's, the dock's, the desktop's) move the selection as the panel's own
  do, in the pin's order, and when the session goes on to the next track by
  itself the selection follows (`Shell::select_track`): the panel never
  holds a session the pin has let go of, and the list shows what plays. One reader pulls a
  session's updates, the panel when it shows the session, otherwise the pin,
  which keeps a film's last frame for the dock. The pin walks a queue of
  paths, the folder's files of the same kind in the pane's order or the
  playlist's tracks (resolved on a worker), opens the next on a worker, and
  hands over at the end of a track.
- The dock (`dock.rs`) is the pinned player's home: a strip at the foot of
  the preview panel with the cover or the film, a bar meter of the spectrum,
  the transport, the seek bar and a close button. Its height is dragged on
  its top edge and remembered with the window's shape, a preference decided
  in render like the panel's width, never a measured size: below `TALL_FROM`
  a row, above it the panel's halo figure; a film takes whatever height it
  is given (`VIDEO_HEIGHT` when pinned into a compact dock). It steps aside
  while the panel shows the pinned session itself or is on its way to a
  track that will (`Shell::dock_shown`), and while the panel is
  closed the last pane's footer keeps a strip of the controls instead, so the
  controls move but are never lost. Only its picture answers clicks as a
  player (`Flash::Dock`): the film, or the cover (the file's icon without
  one), which stops the click there. In the tall dock that is the cover's
  disc and nothing more (`halo::OnDisc`, placed in prepaint as the halo
  paints it, the click tested against the circle): the ring of the
  spectrum and the room beside it are the figure's, and the disc hides the
  figure's hover, so its accent edge is the limit. A click anywhere else in the dock but
  the transport shows the track in the panel, and shows it as it plays,
  never pausing it. A double click on a film reveals it in
  the panel, which goes fullscreen once it shows the session
  (`fullscreen_wanted`). The compact row has three forms measured by
  `AdaptiveRow`, richest first: the meter beside the text with the text
  whole, beside it with the text at least `TEXT_LEAST` wide, and under the
  text, so the meter never costs the title its end; beside the text it is
  as tall as the two lines and takes what the panel has beyond the text. The dock's keys
  (`Player` context: Space, Left,
  Right, Shift+Left/Right, M) send the same `PlayerRequest`s as the desktop.
- What plays is core data. `App::player` holds `playing::NowPlaying`, which
  the shell publishes once per wake for the pin or, without one, the audio
  preview; listeners hear of changes, not of time passing, and work out the
  position themselves. What others want of the player is a `PlayerRequest`
  left there (`ui.player` for the UI's own surfaces) and taken when the shell
  next wakes: nothing calls into the UI from another thread. The wake itself
  takes them (`Shell::sync` from the wake task), not the frame it asks for:
  a window on a workspace that is off screen is never drawn, and a media key
  pressed there must act at once, as must a track ending.
- A file manager is a player only while it is one. Selecting a song is not
  playing it: the preview's track is announced (`NowPlaying`) once it starts
  to play, on that transition, and no longer after Stop or when the selection
  moves on; a pin is announced as long as it lasts. The cover of what is
  announced is written on a worker under the cache, per process
  (`player::COVERS`, swept at start like extracted members), one file per
  track so that a widget caching by location sees it change.
- The desktop's media controls are a plugin (`mpris`) that mirrors
  `App::player` onto the session bus and knows nothing else: properties are
  read from the record, calls become `PlayerRequest`s, the bus name is
  per process and held only while something is announced, and a run without
  a session bus logs once and does without. `player.request` and `player.now`
  are the same surface for scripts and agents. Test it on a private bus
  (`dbus-run-session`), never on the user's.
- ReplayGain is a setting of the audio and video plugin (`preview-media.replay_gain`:
  off, per track, per album), carried to the worker as `Tuning` when a
  session opens: it applies from the next track, never mid-stream. The
  worker's audio filter is then `rgvolume` and `rglimiter` ahead of
  `scaletempo` and `spectrum`; `rgvolume` reads the gain from the stream's
  tag events itself once it flows (nothing is fed to it), and a track without
  tags passes unchanged.
- Gapless. `MediaSession::play_next` names the file to go on with; the worker
  hands it to playbin3 in `about-to-finish`, from the streaming thread, taking
  only what the loop left for it, and reports `Advanced` when the new stream
  starts, clearing position and tags. The pin queues the next track as soon
  as one starts and only follows the switch (`Pinned::advance`); a session
  that cannot do this refuses `play_next` and the pin opens the next track
  itself at the end, with a gap. Verified: one worker process carried three
  tracks.
